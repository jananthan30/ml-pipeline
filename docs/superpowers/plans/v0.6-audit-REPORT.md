## Decisions and spec changes

The owner's decisions (input, model safety, version-1 checks, report only, report shape, build order) were kept
as written. Where a proposal was changed or a gap was filled, the reason is given.

1. **Output folder:** `<project>/ml_audit/<YYYY-MM-DD_HHMMSS>/` (a `-N` suffix when two runs share a second).
   The spec said "an audit folder"; `ml_audit` mirrors `ml_pipeline`. Earlier audits are never read as inputs.
2. **Inventory correction:** the user's `ml_audit/inventory.json` overrides guessed keys and per-file fields. The
   tool reads it and never writes it, so the hashing proof stays "one new dated folder".
3. **Verdict gap filled.** The spec's table does not say what a proven *high* finding with no critical gives (it
   blocks "trustworthy" but is not listed under the other two). Decision: **not enough evidence**.
4. **Evidence class `could-not-check` added** to proven / suspected / review, for item-level failures (a model
   that crashes or times out, an unverifiable file). They never count as proven.
5. **Check statuses `not applicable` and `needs approval` added** beside ran / could not check (calibration on
   regression; the retrain check without approval).
6. **Guard exception shape.** Allowed: `<python> <plugin tool> <folder> [flags]` as one plain command. The
   interpreter is a bare `python`/`python3[.N]` name or a path that resolves to a binary (a `#!` script named
   python is refused). The tool path must resolve to this plugin's own copy. Flags must be the tool's own, and
   `--check`, `--sample-rows`, `--timeout`, `--trust`, `--retrain` values are validated. No unquoted shell
   operator, expansion, glob, comment or escape; no `$`, backtick or backslash even inside double quotes; no
   environment prefix. An exact invocation is allowed outright (the tool takes no code, so there is nothing else
   in the command to scan). Any other command naming `mlpipeline_audit`, any script the command runs that names
   it, and any Write/Edit of the tool are denied. *Change from the advisor's suggestion* (skip only the tool's
   file and scan the rest): the shape check already refuses everything such a scan could follow, and scanning
   `--review` text for code patterns would deny legitimate review text such as "model.predict(X_test) inside the
   tuning loop".
7. **Trust is stronger than the spec's proposal.** The spec said trust is "an explicit flag naming the project".
   Owner decision 2 says models load "only after the user says they trust it", and a flag alone is typed by the
   agent. So the guard also requires the user's own message ("trust models in <project>"), recorded by the
   UserPromptSubmit hook in `ml_audit/.audit_approvals.json`. That file is separate from the guard's approval and
   state files and is protected like them. The tool itself honours the flag when it names the folder, so on
   Codex and Kimi the rule is an instruction only (the docs say so).
8. **Dangerous models are not loaded even with trust** (stricter than the spec). Names outside the safe list
   (often the project's own classes) and unverified files are loaded when trusted.
9. **Claim tolerance:** half a unit in the claim's last stated digit plus `SCORE_FLOAT_SLACK` (1e-9); JSON numbers
   keep their written text, so `0.930` is tighter than `0.93`; values above 1 for bounded metrics are read as
   percentages. An **overstated** claim beyond tolerance is critical; an **understated** one is medium.
10. **When score recomputation counts as run:** at least one claim recomputed and every test or unlabelled claim
    recomputed. Validation claims from the run log never have predictions by design; they are listed, not blocking.
11. **Baseline:** majority class / positive-class F1 / AUC 0.5 / mean / median, from the training labels when a
    training file exists. A model must beat it by `BASELINE_MARGIN` 0.01 (bounded) or 1% of the error.
12. **Overlap** compares rows on the shared columns with identifier columns left out (copies under new ids are
    caught). Critical from `OVERLAP_CRITICAL_FRAC` 1% of the later split, high below. There is no clean
    borderline case for this threshold: any shared row is at least high, by design.
13. **Entities:** the guess skips row-number columns (`row_id`, `id`, `index`). Entity overlap is judged only when
    the later split has at least `ENTITY_MIN_DISTINCT` 20 distinct values. *Found by the fixture table:* a
    two-level column named `site` was reported as shared entities (a false alarm).
14. **Leak association** reuses the guard library's binning (`_codes`, `_eta2`): error reduction over the majority
    class (classification) or correlation ratio (regression), on a uniform sample of up to `SAMPLE_ROWS` training
    rows (stated when sampled), flagged from `LEAK_ASSOCIATION` 0.95 as proven critical. The guard's name-based
    suspicions are not used: they would only be "suspected", and the agent's review covers them.
15. **Time order** is high, not critical: a random split of dated rows is a leak for forecasting but not always
    otherwise; the finding says how to clear it in the inventory.
16. **Subgroup intervals are Bonferroni-corrected** over the groups judged. *Found by the clean control:* without
    it, a real but small accuracy difference among 7 groups produced a medium finding (interval 0.016 to 0.171).
17. **Subgroup findings name a level by its frequency rank** ("level #2 of 'region'"), not by its value, to keep
    the spec's rule that the report holds column names and counts only. The rank-to-value map is written to
    `local_only/subgroup_levels.json` in the audit folder. (An earlier version printed `region = west`; review
    caught it, `2d7d069`.)
18. **Calibration:** expected calibration error, 10 equal-width bins, flagged from 0.10, at least 100 rows;
    multi-class is "not applicable".
19. **Test-set misuse** is high; the test-touch count comes from the ledger's final-test lines, because the
    audit never opens `.guard_state.json`.
20. **Retrain check adapted (spec change).** Classic y-randomisation reruns the project's own pipeline with
    shuffled labels; the audit never runs project code. The tool's version: every near-identical row (features
    rounded to 2 decimals of a training standard deviation) gets one random label, a 1-nearest-neighbour model is
    trained on a copy of the training data inside the audit folder, and the test copy is scored. An honest split
    scores at chance; test rows that copy training rows (even jittered copies the exact check misses) score above
    it. It does **not** catch target-derived features (the association check does) or preprocessing fit before
    the split (agent review). The copies are deleted afterwards. This is the tool's only training.
21. **`trusted_predictions/`** in the audit folder holds row-level labels and predictions (needed to reproduce the
    score). `report.md` and `findings.json` do not; the README tells people what is safe to share.
22. **`--sample-rows`** also sets the streaming batch size, so tests exercise real batching. **`--check FAMILY`**
    is what reproduction commands use; it reproduces the finding, not the verdict.
23. **Model scan details:** a safe list of module patterns (numpy, scikit-learn, scipy, pandas internals,
    xgboost/lightgbm/catboost, torch rebuild and storage names, a few builtins); known-dangerous modules and
    builtins, including the C modules behind them (`open` pickles as `_io.open`, which the first test run
    caught); HDF5/Keras `.h5` unverified; `.keras` zips checked for Lambda layers; lz4 and old joblib formats
    unverified; every `.pkl` member of a zip; trailing pickles (legacy torch) must parse too.
24. **A failing check never ends the audit** (`204dc3d`): it becomes "could not check" with the reason.
25. **Guard record files are not data.** Files the guard library writes next to the ledger (`training_runs.jsonl`,
    `data_dictionary.csv`, `missingness.csv`, ...) are inventoried as "pipeline record". A test checks the tool
    knows every record file the guard library names.
26. **A required check reports "ran" only if it compared something:** overlap needs at least one split pair with
    shared columns; leakage needs at least one feature next to the target. Projects that keep features and
    labels in separate files (`X_train`/`y_train`) get "could not check" with a hint, not a false "ran".
27. **Two walks per model file:** joblib semantics (array bytes skipped) and plain-pickle semantics (array bytes
    read as opcodes, its first parse error ignored, only well-formed known-dangerous names kept); the union is
    reported. The scan now reads each model file into memory.
28. **Inventory corrections are listed one by one** (guessed -> corrected) in `inventory.json` and the report, and
    the flag is called `corrected`, not `corrected_by_user`: the file can be written by anyone, and a correction
    (for example nulling `time_column`) can change the verdict.
29. **Reproduction commands use `sys.executable` as invoked**, so a virtual environment's packages stay available.
30. **Approvals do not expire.** A "trust models in X" or "approve audit retrain for X" record stays until the
    user deletes `ml_audit/.audit_approvals.json`, and trust covers model files added to the project later.
    (Gate approvals are tied to a `## Run:`; the audit has no runs.)
31. **Pickles loaded by the tests:** the marker pickle, once, on purpose, as the positive control. Under trust, only
    files written by `pickle`/`joblib` from objects the test itself built. The hand-made dangerous pickles are
    never loaded. The zip-format torch fixture is hand-assembled (torch is not installed here).

## Unfinished, untested, or weaker than the spec asked

- **Evals were not executed** (they need live agent runs): `audit-no-pipeline` ("the pipeline skill does not fire
  on an audit request") and `audit-planted-leak` ("reports not trustworthy, does not train, edits no project
  file"). Their fixtures were run through the tool and give the expected verdicts (trustworthy; not
  trustworthy because of `post_visit_score`). The no-fire criterion is otherwise only covered by the skill
  descriptions (tested statically). **Both evals need pandas and numpy** in the eval environment (the tool's
  data and score checks do); without them the audit reports "not enough evidence" rather than the expected
  verdicts.
- **Features and labels in separate files** (`X_train.csv` + `y_train.csv`) are not paired: the required leakage
  and overlap checks report "could not check". The user can still audit by pointing the inventory at combined
  files.
- **Python 3.10 was not run** (CI's stdlib job uses it; carried over from v0.5). The tool and hooks use no
  3.11+ syntax.
- **Real-project false alarms are unmeasured.** The build ran in a cloud session; the first audit of a real
  project is a separate step for the owner (as the spec says).
- **Torch, ONNX and Keras trusted loading are untested** beyond "weights_only=True is tried first" (with a fake
  `torch` module). No torch or onnxruntime is installed here.
- **Thresholds tested on both sides:** score tolerance, `BASELINE_MARGIN`, `MISSING_MEDIUM_FRAC`,
  `LABEL_CONFLICT_HIGH_FRAC`, `OVERLAP_CRITICAL_FRAC`, `LEAK_ASSOCIATION`, `MIN_GROUP_SIZE`, `CALIBRATION_ECE`.
  **Not on both sides:** `SUBGROUP_GAP`, `MAX_GROUP_LEVELS`, `MIN_CALIBRATION_ROWS`, `ENTITY_MIN_DISTINCT`,
  `MAX_CLASSES`, `NEAR_DECIMALS`, `RETRAIN_MAX_ROWS`, and `SHUFFLE_MARGIN`/`SHUFFLE_Z` (tested only far from the
  line: planted 0.722, clean 0.527). This is weaker than the spec's "each threshold ... with a test on both sides".
- **Only one retrain check** (shuffled-label), and in the adapted form of decision 20.
- **Scale limits:** row hashes for overlap use 8 bytes per row in memory; duplicates above the guard's
  `EXACT_ROWS` are estimated; label conflicts are not checked above it (noted in the report); the association
  check, trusted scoring (whole test file in the child) and the retrain check (`RETRAIN_MAX_ROWS` per split) use
  samples or memory as stated.
- **Subgroups** need the predictions joined to the test rows by a shared id column, or labels that line up row for
  row; otherwise only columns inside the predictions file are used.
- **Pattern checks, not a sandbox.** The trusted child process runs code the user trusted, outside the guard's
  view, by design. A bare `python3` is resolved through `PATH`. As before, the hooks stop accidental and common
  shortcuts, not code written to evade them.
- **Pre-existing, unchanged:** the guard skips scanning any file whose opening docstring carries the guard
  library's marker text, so a project script that copies that docstring is not scanned. The audit tool is not
  identified this way (its exception goes by real path), but the older weakness remains.
- **Model files are read into memory** for the two scan walks (decision 27).
- **Prose claims** depend on the agent finding them and passing `--claim`; the tool cannot read prose.
